# 章节标题排版（字号放大 + 居中）

- 状态：**已完成**（2026-09-28）
- 类型：UI 调整 + Bug 修复（顺带）
- 创建日期：2026-09-28
- 关联需求：无（用户实测反馈，在「阅读页自绘滚动条」验收后提出）

## 需求描述

用户原始反馈：

> 再小改一下：把每一章节的标题字号适当调大，并且居中。

## 需求背景

阅读页此前**不给章节标题任何区别**：标题和正文段落是同一种 `<p>`，同样的字号、同样的段首缩进。
目录面板能跳章节，但正文里看不出章节从哪里开始。一本几百章的小说，滚动时没有任何「换章了」的视觉落点。

## 当前项目状态

- 章节识别（`detectChapters`）在打开书籍时算出 `[{ index, paragraphIndex, title, number }]`，只喂给目录面板。
- 正文由 `createParagraphWindow` 渲染成 `<p data-paragraph-index="n">`（窗口内约 401 段），
  样式只有一条 `.reader-content p`。窗口只认识段落序号，**不知道哪些序号是章节标题**。
- 屏幕外段落的高度靠 `estimateParagraphHeight` 估算，估算常量与 `src/styles.css` 绑死
  （`letter-spacing .015em`、段首缩进 `2em`）——标题一旦换字号，估算也必须跟着换。

## 变更原因

给标题一个与正文不同的视觉层级，让「翻到新的一章」在正文里可见。这是排版问题，不改结构。

## 影响范围

- 受影响模块：`src/reader.js`（估算函数与窗口）、`src/main.js`（建窗口时传入章节序号）、`src/styles.css`（标题样式）。
- **数据结构：无变化**，`library.json` 不新增字段、不需要迁移。
- **用户数据：无影响**。目录仍然只在打开时现算、不落盘（第 4 节的决策不变）。
- 需要更新 `docs/PROJECT.md`（第 4.4、4.4.1、8 节）。

## 技术实现方案

1. **倍率放在一处**：`src/reader.js` 导出 `CHAPTER_SCALE = 1.3`，`src/styles.css` 用
   `font-size: calc(var(--reader-font-size) * 1.3)`。两边必须同源——屏幕外段落只有估算高度，倍率不一致
   就把误差写进偏移表，跳章节会落不准。这沿用了既有做法（估算常量本来就是与样式表绑死并写注释说明的）。
2. **估算跟进**：`estimateParagraphHeight(text, layout, chapter = false)`。标题按放大后的字号算一行放得下几个字，
   且**没有段首缩进**（居中）。段间距是 `em`，跟着元素自己的字号走，所以也用放大后的字号。
   第三个参数默认 `false`，既有调用与测试不受影响。
3. **窗口按序号加类名**：`createParagraphWindow({ …, chapterIndexes })` 收一个 Set，
   `paint()` 里 `isChapter(i)` 命中就渲染成 `<p class="reader-chapter">`，`reestimate()` 里同样按它换字号。
   目录已经把序号算好了，不必让窗口认识章节对象。
4. **样式**：`.reader-content p.reader-chapter { font-size: calc(var(--reader-font-size) * 1.3); text-align: center; text-indent: 0; }`。
   居中必须显式去掉缩进——`text-indent` 会把居中后的那一行往右推。
   `font:` 简写里的行高是无单位倍数，随字号自动放大，不需要另写。

### 顺带修掉的落点漂移（实现中被测试抓到）

改完之后 `windowing` 用例失败：**改字号后视口顶部从第 3150 段退成第 3149 段**（正是这条用例要守的
「改字号后落点不漂移」）。原因不在标题本身，而在 `paint()` 写 `scrollTop` 这一侧：

- 浏览器把 `scrollTop` 按设备像素取整，**实测是向下取整**；偏移表里是浮点高度。
- 目标值 `offsets[anchorIndex] - anchorViewportOffset` 的小数部分大时，落点会比目标低近 1px，
  反查就落到上一段。读侧那半像素容差（`OFFSET_EPSILON = 0.5`）挡不住写侧的这一整像素。
- 倍率改动把估算高度的小数部分挪过了边界，这条一直存在的隐患才显形——**不是本次排版引入的**。
- 修法：`paint()` 写完 `scrollTop` 读回来核对一次，落点早于锚点就补 1px。代价是一次读取
  （测量循环刚刚读过元素几何，不会多出一次布局）。

### 被否决的替代方案

- **把标题写成 `<h2>`**：会改变文档大纲语义，且标题本来就是正文里的一个段落，`<p>` + 类名与
  「段落是滚动定位的最小单位」这一现有模型一致。
- **用 `em` 写在 CSS 里、估算侧另存一个数字**：两边各写一份数值，早晚会改歪一个，见上面第 1 条。

## 潜在风险

| 风险 | 处理 |
|---|---|
| 标题换字号后，屏幕外段落的高度估算偏了，跳章节落点不准 | 估算与样式共用同一个倍率；`windowing` / `toc-jump` 用例断言跳转后顶部正是该章标题 |
| 既有断言「首段字号 = 正文字号」被标题污染 | 夹具首段恰好就是章节标题。`settings-persist` 与 `windowing` 中取「第一个 `p`」的地方改为取 `p:not(.reader-chapter)`，并加常量与注释说明原因 |
| 居中后标题看起来偏右 | `text-indent: 0`；`toc-jump` 用 `Range` 量文字本身的盒子，断言文字中心与版心中心对齐（`p` 是块级元素，自身矩形恒占满版心，量不出居中） |

## 验收标准

1. 章节标题字号是正文的 1.3 倍，且随「字号」设置一起变 ✓（`toc-jump`：标题 23.4px / 正文 18px）
2. 标题**居中**，文字中心与版心中心对齐 ✓（`Range` 量文字盒子，误差 ≤ 2px）
3. 标题没有段首缩进，正文仍有 ✓（标题 `text-indent: 0px`、正文 36px）
4. 窗口内每一段「第N章 …」都带 `reader-chapter` 类 ✓（逐段核对，0 段缺失）
5. 屏幕外段落按放大后的字号估算高度 ✓（单元测试：一行 30 字、em 段间距随之放大、不缩进）
6. 跳章节、改字号后落点不漂移 ✓（`windowing`、`toc-jump`）
7. 四套主题下的观感 ✗ **未逐一套截图确认**（标题只继承主题的文字色，未新增颜色）
