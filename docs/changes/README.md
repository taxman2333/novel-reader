# docs/changes/ — 需求变更方案与实施记录

本目录保存**每个具体需求的变更方案与实施记录**。

## 文件命名

```
YYYY-MM-DD-简短中文名称.md
```

例如：

```
2026-09-28-章节目录.md
2026-10-02-修复夜间主题对比度.md
```

重名时追加序号，**不要覆盖已有文件**。

## 文件状态

每份方案在顶部标注状态：

| 状态 | 含义 |
|---|---|
| `待实施` | 方案已生成，等待用户确认 |
| `已确认` | 用户已确认，可以执行 `/implement` |
| `实施中` | 正在实现 |
| `已完成` | 已实现并更新文档，**保留文件，不要删除** |
| `已放弃` | 经分析决定不做，保留原因说明 |

## 产生方式

- `/change <需求>` 创建方案文件，状态为 `待实施`
- `/implement` 实施方案，完成后把状态改为 `已完成` 并补充实施记录

## 规则

- **不要删除历史需求记录**，完成的方案也要保留，它们记录了当时的决策依据。
- 方案中的"影响范围"与"数据结构变化"是后续维护的重要线索。
- 如果新需求会影响某份未完成方案，**先指出冲突**，不要擅自合并或覆盖。
