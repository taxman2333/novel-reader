## 需求描述

**用户原始表述**：

> 我阅读小说的时候需要直接定位到某个章节，自己手动翻找太麻烦了，你帮我加个目录功能（根据小说文件中每个章节都有的标题，比如第一章...，来生成目录；或者你有更好的方式也可以）

**澄清后的准确表述**：

1. 打开一本书后，能通过一个目录面板看到该书的章节列表。
2. 点击某个章节，正文直接定位到该章节开头。
3. 章节由小说文本中的标题行自动识别，不需要用户手工维护。
4. 已确认的两个决策：
   - **兼容两种 TXT 分段格式**（空行分段 / 一行一段无空行），即本次一并修正段落切分策略。
   - **识别不出章节时降级为按百分比跳转的滑块**，而不是只给一句提示。

**不在本次范围**：上一章/下一章按钮、章节书签、章节内搜索、章节目录持久化、EPUB 等其他格式。

## 需求背景

小说动辄数百章、数十万字，当前唯一的定位手段是在正文里连续滚动。用户要在中途换章阅读时，只能靠滚动条拖动加肉眼辨认，成本很高。

`docs/ROADMAP.md` 已把该需求列为既定扩展方向，并给出硬性约束：

> 方案对它的约束是：**章节识别失败不能影响全文阅读**，即必须可降级。

本方案的两个降级层次（识别失败 → 百分比跳转 → 目录面板可关闭、不影响正文）满足该约束。

## 当前项目状态

### 段落解析：只认空行，会抹平段内换行

`src/reader.js:1-18`：

```js
export function parseParagraphs(text) {
  const normalized = text.replace(/\r\n?/g, '\n').trim();
  if (!normalized) return [];
  const paragraphs = [];
  let cursor = 0;
  for (const rawParagraph of normalized.split(/\n\s*\n+/)) {   // ← 只按空行切
    const paragraph = rawParagraph.replace(/\n+/g, '').trim();  // ← 段内换行被删掉
    ...
  }
}
```

`electron/book-service.js:48-56` 的 `normalizeText()` 只做换行符统一与行尾去空格，**不会补插空行**。

因此：**一本「一行一段、没有空行」的 TXT（网文抓取版极常见）会被解析成一个段落**，整本书渲染成单独一个 `<p>`。这既让目录无法定位，本身也是阅读排版的缺陷。这是本方案必须一并处理的前置问题——否则目录功能对相当一部分文件完全无效。

### 正文渲染：全部段落一次性落 DOM，每段带索引

`src/main.js:171`：`<p data-paragraph-index="${index}">`。正文一次性全部渲染，所以「跳到第 N 段」只需 `scrollIntoView`，与 `restoreScroll()` 用的是同一机制（`src/reader.js:48-56`），可直接复用。

### 阅读进度：滚动防抖保存，恢复顺序为上下文 → 段落索引 → 比例

`src/main.js:224-230` 滚动监听 → `getProgressFromScroll()` → 500ms 防抖 → `persistLibrary()`。跳转本身会触发 scroll 事件，因此**进度保存无需额外代码**。

注意 `findRestoreIndex()`（`src/reader.js:36-46`）的第三个分支（按 `ratio` 回退）实际上是死代码：`paragraphIndex` 经 `normalizeProgress()` 后恒为有限数字，第二个分支必然命中。这一点与下面的兼容性风险有关。

### 面板：已有右侧抽屉式面板可参照

`renderSettingsPanel()`（`src/main.js:292+`）输出 `.settings-scrim` + `.settings-panel`，配合 `toggleSettings()` 开关。目录面板沿用同一形态。夜间主题的适配规则目前是按 `.settings-panel` 类名逐条写的（`src/styles.css:83-92`）。

## 变更原因

不改则用户只能继续手动滚动找章节，需求无法满足。段落切分那处不一起改，则目录对「无空行 TXT」这类文件完全失效——功能形同虚设。

## 技术实现方案

### 1. 段落切分：按空行占比自动选择

在 `parseParagraphs` 中先统计空行占比，再决定分隔符：

```js
const lines = normalized.split('\n');
const blankRatio = lines.filter((line) => !line.trim()).length / lines.length;
// 空行分段的文件里约有一半行是空行；无空行文件占比接近 0。0.15 是两者之间
// 明显的分界，不依赖精确取值的调参。
const blocks = blankRatio >= 0.15 ? normalized.split(/\n\s*\n+/) : normalized.split(/\n+/);
```

两种情况下 `charOffset` 仍是 `normalized` 中的偏移，语义不变。

**被否决的替代方案**：只按 `\n` 切分并靠「行是否为空」过滤。对空行分段文件会把每段正确处理，但对「段内本来就有换行的软换行文本」会切得过碎。按占比选择能同时照顾两类。

### 2. 章节识别：在段落上匹配，三重约束控制误判

新增 `src/reader.js` 导出：

```js
export function detectChapters(paragraphs) // → [{ index, paragraphIndex, title, number }]
```

**为什么扫段落而不是扫原始文本行**：段落是滚动定位的最小单位，行号无法直接映射到 DOM 节点。完成第 1 步后，无空行文件也是一行一段，两种格式下标题都恰好是独立段落。若仍扫原始行，反而要额外维护「行 → 段落」映射，且那层映射在空行分段文件里是多对一、更容易出错。

**标题模式**（锚定在段落开头，尾部标题限长）：

```js
// 第一章 / 第1章 / 第一百二十三章 / 第 12 回 / 正文第一章 …
const NUMBERED = /^[【\[（(《]?\s*(?:正文\s*)?第\s*([0-9０-９零〇一二三四五六七八九十百千万两壹贰叁肆伍陆柒捌玖拾佰仟]+)\s*([章节回卷部篇集])\s*[】\]）)》]?\s*(.{0,24})$/;
// 序章 / 楔子 / 前言 / 番外 / 尾声 …
const SPECIAL  = /^[【\[（(《]?\s*(序章|序言|序|楔子|引子|前言|后记|尾声|终章|番外篇?|附录|作者的话)\s*[】\]）)》]?\s*(.{0,24})$/;
```

三重约束：

1. **锚定段首**：正文里提到「第一章」的句子不会命中。
2. **尾部限长 24 字**：标题段落总长被限制在约 34 字内。`第三部分的内容如下……` 这类句子通常远超此长度。
3. **序列合理性**：把中文数字解析为整数后，检查相邻编号是否大体递增。数字型标题中非递减的比例低于 60% 时，判定为「不像目录」，整本放弃识别并降级。这条专门对付标题格式被误判成章节的散乱命中。

中文数字解析用一个独立的 `parseChineseNumber()`，处理 `一`～`万` 与 `十一 = 11` 这类规则。

**识别失败判定**：候选章节少于 2 个，或未通过序列合理性检查。

### 3. 目录面板

- **入口**：工具栏右侧新增「目录」按钮。工具栏是 `grid-template-columns: 1fr auto 1fr`（`src/styles.css:66`），把「目录」与「Aa」包进一个 `.toolbar-actions` 容器作为最后一个子元素，保留现有 `justify-self: end` 的对齐。
- **形态**：右侧抽屉，与阅读设置一致。把 `src/styles.css` 中 `.settings-panel` 相关规则泛化为共用的 `.side-panel` 类（纯类名替换，约 12 处），两个面板同时套用，夜间主题适配自动生效。**被否决的方案**：目录做成全屏列表页——引入新的视图状态，且与现有面板风格割裂。
- **内容**：
  - 识别成功：可滚动的章节列表，每项 `<button data-chapter-index="i">`，显示章节标题（超出省略号截断）。当前章节加 `.is-active`。
  - 识别失败：显示「未识别到章节标题」，下方是按百分比跳转的滑块。
- 打开目录时自动关闭阅读设置面板，反之亦然。

### 4. 跳转与当前章节高亮

**跳转**：`scrollIntoView({ block: 'start', behavior: 'instant' })`。

必须显式指定 `behavior: 'instant'`：`.reader-scroll` 有 `scroll-behavior: smooth`（`src/styles.css:72`），跨几百章的平滑滚动会是一次漫长的连锁动画。跳转后关闭面板，滚动事件自然触发既有的 500ms 防抖保存，**不需要额外的进度保存代码**。

**当前章节**：在既有的滚动监听里，用 `getProgressFromScroll()` 已经算出的 `paragraphIndex` 反查所属章节（最后一个 `paragraphIndex <= 当前索引` 的章节），仅在章节变化时更新 DOM。

刻意**不**在滚动事件里做几何测量（`getBoundingClientRect`）：那会在每次滚动时强制同步布局。代价是章节高亮基于「比例 × 段落数」的估算，段落长度差异大时可能偏一章——这与应用现有的阅读进度模型是同一套近似，保持一致比引入两套口径更好。此项列为已知限制。

### 5. 百分比跳转降级

仅在识别失败时渲染。滑块 `input` 事件 → `scroll.scrollTop = pct / 100 * (scrollHeight - clientHeight)`。同时显示当前百分比，滚动时同步更新。

## 兼容性问题

### 1. 无空行 TXT 的阅读进度可能一次性失效（**需要用户知悉**）

段落切分策略改变后，原本「整本一个段落」的文件会变成数千个段落。旧进度记录里保存的是 `paragraphIndex: 0` 与旧段落的前 240 字上下文。

恢复时 `findRestoreIndex()` 先按上下文匹配：切分后没有任何一个段落包含那 240 字（它们被拆散到多个段落里），匹配失败；随后落到 `paragraphIndex` 分支，返回 0——**书籍会从开头打开**。

- **影响面**：仅限「无空行」的 TXT。有空行分段的文件段落切分结果完全不变，进度不受影响。
- **发生次数**：一次性。之后保存的进度就是新口径的。
- **缓解**：本次新增的目录恰好让「重新找到位置」变得容易，实际代价很低。
- **不作为本次范围**：让 `findRestoreIndex()` 在上下文失配时改用 `ratio` 回退，会改变**所有**书籍（含文件变更场景）的恢复行为，属于独立的行为变更，应单独评估。本次仅在文档中记录该缺陷。

### 2. 阅读排版变化（预期内的改善）

无空行 TXT 从「一整块文字」变成正常分段。这是修正，但对用户是可见变化。

### 3. 阅读设置与书架记录

完全不受影响。

## 验收标准

1. `detectChapters()` 对含「第一章 / 第1章 / 第一百二十三章 / 序章 / 番外」的合成段落，返回的章节数量与 `paragraphIndex` 正确。
2. 正文段落 `第三部分的内容如下，我们需要……`（超过限长）**不会**产生章节项。
3. 一本无空行 TXT 打开后段落数 > 1，且目录可用。
4. `npm run test:ui` 新增的 `toc-jump` 用例通过：打开目录 → 断言章节数 → 点击第 N 章 → 断言视口顶部段落索引等于该章 `paragraphIndex`。
5. **反向验证**：暂时破坏章节识别（如让 `detectChapters` 直接返回空数组）后，`toc-jump` 必须失败；验证后完整还原，`git diff -- src/` 为空。
6. `npm test` 原有 12 项仍全部通过，新增测试一并通过。
7. **目录不落盘**：打开书籍并跳转章节后，`library.json` 的字段与体积与改动前一致，无任何新增字段。
8. 识别不出章节的书，目录面板显示百分比滑块，拖动后阅读位置随之改变。

### 实现与方案的偏差

1. **`SPECIAL_HEADING` 去掉了单字「序」**。方案正则写作 `(序章|序|…)`，但单字「序」会让「序幕已经拉开……」这类正文短句混进目录。按「宁可漏判」的既定取向移除。
2. **界面用例新增两条而非方案写的 `toc-jump` 一条**。验收标准 8 要求验证降级路径，而 `toc-fallback` 同一用例顺带覆盖了标准 3（无空行切分），合并成一条需要同时断言两件事、失败时难以定位，因此拆成两条。
3. **夹具改为双变体**，而不是在单一文本里同时塞进两种分段格式。`.plain` 变体同时服务标准 3 与 8；`spec.text` 决定每个用例用哪份。
4. **`tests/ui/harness.mjs` 也在改动范围内**（方案的文件清单未列）。`topParagraphIndex` 原本只返回索引，断言「跳转后顶部是某章标题」需要文本。
