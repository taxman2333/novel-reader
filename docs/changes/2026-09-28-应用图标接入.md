# 应用图标接入

- 状态：已完成
- 类型：UI 调整 / 构建配置
- 创建日期：2026-09-28
- 关联需求：`design/app-icon/README.md`（图标设计资产与设计说明）

## 需求描述

把已经选定并完成设计的应用图标（`design/app-icon/final/`，方案 B「打开的书型」）接进应用：

1. 打包产物的 exe 使用该图标，使它在资源管理器、任务栏、开始菜单中显示正确；
2. 应用窗口自身使用该图标，开发态也能看到；
3. 版本号升到 1.0.1，为发布新 Release 做准备。

图标本身的设计工作已在上一轮完成并入 `fa5d1f1`，本方案只处理**接入**。

## 需求背景

v1.0.0 发布时打包产物沿用 Electron 默认图标，这一条被明确记在 `docs/CHANGELOG.md` 的
「已知问题」与 Release 说明的「已知限制」里。图标现已设计完成，需要真正装上。

## 当前项目状态

- 图标资产已入库：`design/app-icon/final/icon.svg`（矢量源）、`icon.ico`
  （7 项：16/24/32/48/64/128/256，PNG 内嵌写法）、各尺寸 PNG。
- `package.json` 的 `build` 段**没有** `win.icon`；`build.files` 白名单为
  `["dist/**", "electron/**", "package.json"]`。
- `electron/main.js` 的 `createWindow()` 创建 `BrowserWindow` 时**没有**传 `icon`。

## 变更原因

不改的话，用户拿到的 exe 与窗口显示的都是 Electron 默认图标，与已经完成的产品视觉不一致。

## 影响范围

- 受影响：打包配置（`package.json` 的 `build`）、主进程窗口创建（`electron/main.js`）、
  版本号、分发产物。
- 不受影响：**功能代码零改动**，渲染层、数据结构、IPC 接口、`library.json` 全部不动。
- 用户数据：**完全不受影响**，本次不涉及存储。

## 技术实现方案

三处改动：

1. `package.json` → `build.win.icon: "design/app-icon/final/icon.ico"`
   构建时读取，由 electron-builder 嵌入 exe 资源段。构建期路径，不受 `files` 白名单约束。

2. `package.json` → `build.files` 增加 `"design/app-icon/final/icon.ico"`
   **这一步是必需的，是本方案最容易漏掉的地方。** 打包后代码运行在 `app.asar` 内，
   `BrowserWindow` 的 `icon` 是**运行时**读取的，文件必须真的在 asar 里。
   不加白名单的表现是：开发态图标正常，打包后窗口与任务栏退回默认图标 —— 而且不报错。

3. `electron/main.js` → `BrowserWindow` 增加 `icon: APP_ICON`
   路径写成 `path.join(__dirname, '..', 'design', 'app-icon', 'final', 'icon.ico')`。
   开发态 `__dirname` 是仓库的 `electron/`，打包态是 `app.asar/electron/`，
   两种情况下该相对位置都成立，**同一个表达式两边通用，图标只保留一份，不做副本**。

### 被否决的替代方案

| 方案 | 否决原因 |
|---|---|
| 把图标复制到 `electron/` 下（已在白名单内） | 同一份图标存两处，改一处忘一处会导致两边不一致 |
| 复制到 electron-builder 默认的 `build/icon.ico` | `/build/` 在 `.gitignore` 里且锚定仓库根目录，图标会被静默排除在上传之外 |
| 只设 `build.win.icon`，不设 `BrowserWindow.icon` | 打包后 exe 与任务栏图标正确，但开发态窗口仍是 Electron 默认图标 |

### exe 图标如何验证的

「构建成功」不等于「图标换掉了」，所以没有停在构建日志上，而是**解析 PE 资源段做逐项比对**：

1. 读 DOS 头 `e_lfanew` → PE 签名 → COFF/可选头 → 数据目录第 3 项（资源表）RVA；
2. 按节表把 RVA 换算成文件偏移（资源目录内所有偏移都是相对**资源段起点**，不是相对当前节点——这里第一次写错，报 `ERR_OUT_OF_RANGE`）；
3. 遍历目录树取 `RT_GROUP_ICON`(14)，解出 `GRPICONDIR` 的尺寸/位深列表。

结果，并**用已发布的 v1.0.0 zip 里的旧 exe 做对照**：

| exe | RT_ICON 项 |
|---|---|
| v1.0.0（未设图标） | 4 项：16, 32, 48, 256 —— Electron 默认图标 |
| v1.0.1（本次） | **7 项：16, 24, 32, 48, 64, 128, 256** —— 与 `icon.ico` 逐项一致 |

对照实验是关键：单独看新 exe 的 7 项并不能说明问题（Electron 默认图标也含 16/32/48/256），
两者一比才确证图标确实被替换。

另确认分发包里的 exe 就是被验证的那一个：zip 内 `书页之间.exe` 与 `release/win-unpacked/`
下的 exe CRC32 均为 `d9bcbb5c`（同为 186,328,576 字节）。
