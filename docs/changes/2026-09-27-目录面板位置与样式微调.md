- 状态：**已完成**（2026-09-27）
- 类型：UI 调整（纯界面，无逻辑与数据结构变化）
- 创建日期：2026-09-27
- 完成日期：2026-09-27
- 关联需求：`docs/changes/2026-09-27-章节目录.md`（本次是其实施成果的界面微调）

> 实施记录见文末。

## 需求描述

**用户原始表述**：

> 稍微修改一下，把目录的按钮调到最上方区域的左侧，返回键的右边，点击目录按钮，目录从界面的左侧弹出，并且目录中的章节字体调大一号；然后按钮目前是一个"目"字，改为"目录"

**澄清后的准确表述**（四条独立的界面调整）：

1. **按钮位置**：目录按钮从工具栏右端移到工具栏左端，紧邻返回键的右侧。工具栏从左到右依次为：`←`、目录按钮、书名与百分比、阅读设置按钮。
2. **面板滑出方向**：目录面板改为从**界面左侧**滑入，而不是当前的右侧。
3. **章节字号**：目录中的章节条目标题字号调大一号。
4. **按钮文案**：目录按钮从单字「目」改为两字「目录」。

**不在本次范围**：阅读设置面板的位置与样式（仍留在右侧）、目录面板宽度、章节列表的两行截断、目录面板的打开/关闭方式（仍是 × 与遮罩点击）、任何目录识别逻辑。

## 需求背景

`docs/changes/2026-09-27-章节目录.md` 已实施完成。当时的方案把目录按钮放在工具栏右端、与阅读设置按钮同组，面板也复用了设置面板的右侧抽屉形态——这是「与现有面板保持一致」这一取舍的直接结果。

实际使用中这两点都不合适：

- 目录是**导航**动作，返回键也是导航动作，两者相邻才符合直觉；而右端与「阅读设置」放在一起，暗示两者是同类设置项。
- 目录面板是**按章浏览的长列表**，从左侧滑出与「返回书架→目录→正文」这条自左向右的阅读动线一致；右侧滑出更接近属性面板的语义。

字号与按钮文案则是可读性问题：13px 的章节标题在 360px 宽的面板里偏小；「目」是单字缩写，需要用户猜测含义，而工具栏右端的「Aa」至少是通用符号。

### 面板的滑入方向

`src/styles.css:82-94`：

```css
.panel-scrim { position: fixed; inset: 0; z-index: 4; … }
.side-panel { position: fixed; z-index: 5; top: 0; right: 0; bottom: 0; width: 360px; padding: 30px; overflow: auto; …; box-shadow: -15px 0 50px rgb(20 28 20 / 12%); transform: translateX(100%); transition: transform .25s ease; }
…
.side-panel.is-open { transform: translateX(0); }
```

关闭态是 `translateX(100%)`（整体移到视口**右侧之外**），打开态 `translateX(0)`。阴影 `-15px 0` 是朝左投的，为右侧面板而设。

目录面板与设置面板**共用** `.side-panel` 类（这是 `章节目录` 方案里刻意做的泛化）。因此不能直接改 `.side-panel`——那会把设置面板也一并搬到左边，而本次需求明确只改目录面板。

### 章节条目字号

`src/styles.css:95-106`：

```css
.toc-count { … font-size: 12px; }   /* 「共 N 章」 */
.toc-item  { … font-size: 13px; … }  /* 章节条目 ← 本次要调大的 */
```

## 技术实现方案

### 1. 工具栏左侧容器

把返回键与目录键包进 `.toolbar-left`：

```html
<header class="reader-toolbar">
  <div class="toolbar-left">
    <button class="icon-button toolbar-button" id="back-to-shelf" title="返回书架" aria-label="返回书架">←</button>
    <button class="icon-button toolbar-button toolbar-label-button" id="open-toc" title="目录" aria-label="目录">目录</button>
  </div>
  <div class="reader-title">…</div>
  <div class="toolbar-actions">
    <button class="icon-button toolbar-button" id="open-settings" title="阅读设置" aria-label="阅读设置">Aa</button>
  </div>
</header>
```

```css
.toolbar-left { display: flex; align-items: center; gap: 4px; justify-self: start; }
```

**为什么保留 `.toolbar-actions` 这个只剩一个按钮的容器**：`.reader-toolbar > :last-child { justify-self: end; }` 正是靠它把右端内容对齐的。若把 `#open-settings` 提为直接子元素，这条规则会落到按钮本身（也能工作），但会改动既有选择器的语义、牵连更多文件行数。保留容器是更小的改动，代价只是多一层 `div`。

**`.toolbar-left` 的 `justify-self: start` 是显式写出的**，不依赖「按钮有固定宽度所以默认 stretch 不会撑开」这一隐式行为——将来若按钮改为自适应宽度，缺了它会让整个左侧容器被拉伸。

**被否决的替代方案**：把返回键也移进 `.toolbar-actions` 并让该容器靠左。语义上「actions」指右侧操作组，把导航键塞进去会让类名与用途脱节。

### 2. 加宽的文字按钮变体

```css
.toolbar-label-button { width: auto; min-width: 36px; height: 36px; padding: 0 14px; border-radius: 8px; font-size: 15px; }
```

- 与 `.icon-button` 叠加使用（`class="icon-button toolbar-button toolbar-label-button"`），只覆盖尺寸相关的属性，颜色、hover、过渡全部沿用 `.icon-button`。
- `border-radius` 从 50%（圆形）改为 8px（圆角矩形）。**这是刻意的**：两字的按钮做成圆形会在字符与边缘之间留下大块空白。代价是工具栏上同时存在一个圆形按钮（`←`、`Aa`）与一个圆角矩形按钮，视觉上不完全统一——这是「文案为两个汉字」这一要求的必然结果。
- `font-size: 15px` 与 `.toc-item` 调大后的 15px 一致，但不是刻意联动，各自独立。
- `width: auto` 是必须的：`.icon-button` 的 `width: 36px` 会让「目录」两字溢出。`min-width: 36px` 保证它不会比旁边的圆形按钮更矮/更窄。
- **被否决的替代方案**：把「目录」竖排或缩成「目 录」加字距。竖排会让 36px 高度装不下，加字距仍是两字宽度、没有解决问题。

### 3. 目录面板改为左侧滑出

新增一个修饰类，**只加到目录面板上**：

`src/main.js`：`<aside class="side-panel side-panel--left" id="toc-panel" …>`

```css
/* 必须写在 .side-panel 之后：同为一类选择器（0,1,0），靠源码顺序决定关闭态谁生效。 */
.side-panel--left { right: auto; left: 0; box-shadow: 15px 0 50px rgb(20 28 20 / 12%); transform: translateX(-100%); }
```

三点说明：

- **`right: auto` 是必要的**，不是冗余。基类的 `right: 0` 与新增的 `left: 0` 同时存在时属于过约束，LTR 下浏览器会忽略 `right`——依赖这条过约束解析规则才能定位正确，显式写 `right: auto` 让意图不依赖规范细节。
- **阴影方向反向**为 `15px 0`（朝右投），否则左侧面板的阴影会投到视口之外，看起来像没有阴影。
- **不需要写 `.side-panel--left.is-open`**。`.side-panel.is-open { transform: translateX(0) }` 是 `(0,2,0)`，`.side-panel--left` 是 `(0,1,0)`，前者的特异性更高，打开态必然生效。此处刻意不写多余规则，但要在注释里说明理由——否则将来会有人"顺手补上"。

`.panel-scrim` 是 `inset: 0` 的全屏遮罩，与方向无关，**不改**。

### 4. 章节条目字号

```css
.toc-item { … font-size: 15px; … }   /* 原 13px */
```

**只改 `.toc-item`**。「大一号」指的是章节条目本身；`.toc-count`（共 N 章）、`.toc-empty`（未识别到章节的说明）、`.toc-hint` 是辅助信息，调大会喧宾夺主。若实施后觉得不协调，单独调整这几条即可。

**具体数值 15px 属于 `CLAUDE.md` 第 10.3 节所说的"暂时性实现建议"**，可随时替换。备选是 14px（更保守）。选 15px 是因为 13 → 15 才是肉眼可辨的「一号」，13 → 14 在 360px 的面板里几乎看不出差别——但这一判断需要用户在实施后目视确认。

## 潜在风险

| 风险 | 应对 |
|---|---|
| 面板实际没有从左侧滑出（修饰类拼错或被特异性覆盖） | `toc-jump` 增加几何断言：关闭时 `rect.right <= 0`，打开时 `rect.left === 0`；并做反向验证（见验收标准 5） |
| 设置面板被连带搬到左侧 | 断言 `#settings-panel` 打开时仍靠右（`rect.right === innerWidth`）。修饰类只加在目录面板上，但这条断言把「以为改了、其实改错了对象」钉死 |
| 「目录」两字在 36px 圆形按钮里溢出或被截断 | `.toolbar-label-button` 覆盖 `width: auto`；断言按钮 `scrollWidth <= clientWidth + 1`（无内容溢出） |
| 工具栏三栏布局失衡（左侧变宽后书名不再居中） | 左侧容器 + 两字按钮合计约 92px，远小于 `1fr` 栏宽的一半，第二栏仍是 `auto` 居中；在断言里检查书名居中（`|titleRect.center - toolbarRect.center| < 2`） |
| 字号调大后标题截断更早，长章节名看不清 | 已知取舍。360px 面板减 60px 内边距后约 300px，15px 字号约能显示 20 个汉字，超出仍走省略号。若实际不满意，可单独评估「面板加宽」或「两行截断」，**不在本次范围** |
| 目录按钮移到左侧后被面板自身覆盖，无法再次点击关闭 | 这是**可接受的已知行为**：面板打开时本就有 × 按钮与遮罩点击两种关闭方式。原实现在右侧也是同样情况（`togglePanel('toc', true)` 只会打开、不会切换关闭）。**不改为 toggle 语义**——那是行为变更，不是本次的界面调整 |
| 圆角矩形按钮与圆形按钮视觉不统一 | 已知取舍，已在上文说明理由。若用户不接受，可改为「目录」二字缩小到 13px 塞进更宽的胶囊形，或恢复单字图标——均属后续微调 |

## 验收标准

全部可用 `npm run test:ui` 的 `toc-jump` 用例自动断言，或由该用例补充的求值语句验证：

1. **按钮位置**：`#reader-toolbar` 的直接子元素顺序为 `.toolbar-left`、`.reader-title`、`.toolbar-actions`；且 `#open-toc` 的 `rect.left` 大于 `#back-to-shelf` 的 `rect.right`（在返回键右侧），同时 `#open-toc` 位于视口左半部分（`rect.left < innerWidth / 2`）。
2. **按钮文案**：`#open-toc` 的 `textContent.trim() === '目录'`。
3. **按钮不溢出**：`#open-toc` 的 `scrollWidth <= clientWidth + 1`。
4. **面板从左滑出**：
   - 关闭态：`#toc-panel` 的 `rect.right <= 0`（完全在视口左侧之外）。
   - 打开态：`#toc-panel` 的 `rect.left === 0`（左边缘贴齐视口）。
5. **反向验证**：把 `.side-panel--left` 的 `transform` 改成 `translateX(100%)`（等同于退回右侧滑出）后，新增的几何断言必须失败；验证后完整还原，`git diff -- src/styles.css` 只含本次的真实改动。
6. **设置面板未被牵连**：打开 `#settings-panel` 时其 `rect.right === innerWidth`（仍从右侧滑出）。
7. **章节字号**：`getComputedStyle(document.querySelector('.toc-item')).fontSize === '15px'`。
8. **书名仍居中**：`.reader-title` 的中心与工具栏中心相差不超过 2px。
9. `npm run test:ui` **9 项全通过**（数量不变，只增加断言）；`npm test` **24 项全通过**（本次不涉及逻辑）。

### 反向验证（验收标准 5）做了两次

方案原本只设计了一次，实施时发现单次覆盖不全，因此补做：

1. **把 `.side-panel--left` 的 `transform` 改为 `translateX(100%)`**（保留修饰类，只翻转方向）：`toc-jump` 失败，报「关闭时目录面板应完全位于视口左侧之外，实际测得 `{left:360, right:720}`」，9 项中 8 通过、退出码 1。
2. **把 `#toc-panel` 的 `side-panel--left` 修饰类整个删掉**（还原成改动前的真实形态，等价于本次特性未实施）：`toc-jump` 失败，报「实际测得 `{left:1384, right:1744}`」（视口宽 1400，面板确实回到右侧），9 项中 8 通过、退出码 1。

两次都已完整还原：`src/styles.css` 与 `src/main.js` 的 md5 与备份逐一比对一致，全库 `translateX(100%)` 仅剩基类 `.side-panel` 中那一处（本就该有），`src/main.js` 中为 0 处。

**第一次验证暴露了一个覆盖缺口，值得记录**：仅翻转 `transform` 时，**关闭态断言失败但打开态断言会通过**——因为 `right: auto; left: 0` 使面板打开时仍锚定在左侧。也就是说「打开态 `left === 0`」单独并不能证明面板是从左侧滑入的，真正起作用的是关闭态断言。第二次验证（删掉修饰类）才同时覆盖了两条路径。

### 与方案的偏差

**无实质偏差。** 三处需要说明的实现细节：

1. **面板位置断言的等待方式**：方案未提及，但 `.side-panel` 有 `transition: transform .25s`，点完按钮立即读几何会取到动画中间值。新增 `waitForPanelRect()` 轮询到目标位置再断言。虽然 `tests/ui/entry.mjs` 已注入 `force-prefers-reduced-motion`（把过渡压到 0.001ms），仍显式等待——不依赖该开关才能成立。
2. **阅读设置面板的断言改为在页面内比较**：`waitForPanelRect` 是在 Node 侧比较采集到的值，而右侧面板的 `right` 依赖于视口宽度，放在页面内比较才能每轮取到新值。
3. **`toc-fallback` 未改动**：它也打开目录面板，但本次未给它加左侧断言——`toc-jump` 已覆盖，重复断言不会增加保护。
